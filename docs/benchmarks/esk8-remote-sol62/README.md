# Full remote schematic trial: GPT-6.2 Sol

## Scope

This trial repeats the full skateboard-remote schematic stage that an earlier
DeepSeek run left unfinished. The model receives the original user request,
an empty native project, the installed-library snapshot, the complete 101-tool
catalog and the binary's embedded guides. It must choose parts, verify pin
mappings and support circuitry against manufacturer documentation, compose a
readable schematic and save the project with `design-notes.md`.

The task text is the one used by the
[interrupted DeepSeek run](../esk8-remote-schematic-acp/README.md) follow-up.
Only the limits (120 turns, 30 minutes instead of 180 turns, 45 minutes) and
the catalog generated by the current binary differ. The catalog change is the
`schematic_review` description and starting instruction that mention layout
metrics. The prompt does not require `block` placement.

## Result

The saved project has three pages: power and charging, radio and MCU, and user
interfaces. It contains 94 components, 28 of them GND supply symbols.
See [Main](Main.png), [Radio and MCU](Radio_and_MCU.png) and
[User interfaces](User_interfaces.png). The model's report is in
[task-answer.md](task-answer.md) and its notes in [design-notes.md](design-notes.md).

Native structural ERC reports zero findings and returns `partial` because
imported pin metadata is incomplete. Compared with the earlier DeepSeek pages,
local circuitry is drawn with visible wires and the main page uses 16 labels
instead of 60.

Spot checks against the downloaded AXP2101 datasheet match: 1 µF at BAT, two
22 µF at VSYS, 2.2 kΩ pull-ups on SDA/SCK and 4.7 kΩ on IRQ. USB-C CC pins have
5.1 kΩ pull-downs. The nRF52840 has DEC1–DEC6 decoupling with the DEC5 820 pF
capacitor marked DNP for later silicon, VDDH tied to VDD for normal-voltage
supply, and a 32 MHz crystal with load capacitors. The PMIC and display use
separate I²C buses. This is not a complete electrical review; the model itself
lists the AXP2101 DCDC1 startup voltage and crystal availability as unconfirmed.

## Manual layout instead of automatic composition

The three creation documents in [documents/](documents/) place every symbol at
explicit coordinates and give explicit paths for all 97 wire groups. None uses
`block`. The off-grid counts come mostly from symbols placed at the model's own
coordinates (29, 18 and 23 symbol origins).

Asked afterwards ([why-no-blocks-answer.md](why-no-blocks-answer.md)), the model
said it never tried `block` or automatic wiring. It assumed explicit geometry
gave more control over branch order, ground returns and labels around the
AXP2101 and nRF52840, without evidence either way. It would rely on automation
if it could fix the IC and finished groups, place parts relative to particular
pins, preserve local topology such as a feedback tap after the inductor, see
which groups were wired continuously or split into labels, and get collision
checks against rendered ink.

## Feedback

From [feedback-answer.md](feedback-answer.md), as reported by the model:

- Each CLI call starts a new session, so a reviewed preview had to be recomputed
  in the applying batch.
- `schematic_review` reported zero overlaps while text touched capacitor plates
  and a rotated connector field was partly hidden; close-up renders found both.
- No direct way to mark C16 do-not-populate; a raw mutation was used.
- `library_rescan` returned `complete` while rejected elements were only logged
  to stderr.
- Exact MPN searches failed for some parts where an LCSC ID worked.

These observations drive the [work queue](../../roadmap.md#work-queue-2026-11-18).
